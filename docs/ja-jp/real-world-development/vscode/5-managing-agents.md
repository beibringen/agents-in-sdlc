GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業は自分のマシンでリアルタイムに実行されます。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または破棄し、追加のプロンプトを送って作業を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイコントラストモードに加えてライトモードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装中です。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにしたいとのことです。新しい会話を最初から始める代わりに、現在のセッションに指示して作業を追加します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイル編集の差分はチャット内に表示され、**Keep** と **Undo** を選択できます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中はチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取り、編集、実行許可を求めるターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
    - 変更を適用するには **Keep** を選択します。
    - 変更を元に戻してエージェントに再度試させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの呼び出し (ターミナルコマンドの実行など) で許可が必要な場合、エージェントは一時停止し **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントは前の作業のコンテキスト (変更したコンポーネント、使用したスタイル、設定した local storage の方法など) を保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べて、ライトモード用の変更を提案します。
3. 前のハイコントラスト機能と同様に、新しい編集をレビューします。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえばトグル UI を好まない方法でリファクタリングしようとする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加メッセージを送信できます。

> [!TIP]
> 進行中のセッションに指示するほうが、新たに始めるよりも早く作業できます。追加のプロンプトで調整を依頼できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「3つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込む」、「両方の切り替えにキーボードショートカットも追加する」などです。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。アクセシビリティエージェントの指示どおり、ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向を調整しました。ファイル編集を確認して承認または破棄し、コンテキストを保ったまま追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を承認または破棄する方法
- 追加のプロンプトを使って、進行中のセッションに指示する方法

[次のレッスン][next-lesson]では、アクセシビリティ機能を pull request として公開し、このラボを通してローカルのカスタムエージェントが行った変更をレビューします。
